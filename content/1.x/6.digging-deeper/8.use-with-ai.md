Laravel Access Control 1.0 changed most of its API: controls linked by discovery, levels, boundaries, search keys. A coding assistant that learned from code written for an earlier version can write controls that no longer work. The sources on this page give it the current documentation.

## Laravel Boost skill

The package ships a skill for [Laravel Boost](https://laravel.com/docs/boost): a `SKILL.md` file that a coding agent loads when it works on your controls, perimeters, policies or controlled searches.

### Installing the skill

The skill is named `laravel-access-control`. It lives in the package at `resources/boost/skills/laravel-access-control/SKILL.md`, so Laravel Boost finds it in `vendor/lomkit/laravel-access-control` once both packages are installed:

```bash
composer require laravel/boost --dev
php artisan boost:install
```

Select the skill during the installation. After an update of the package, run `php artisan boost:update` so that the agent reads the skill of the installed version. See the [Laravel Boost documentation](https://laravel.com/docs/boost) for its commands and for replacing a package skill with your own.

### What the skill covers

The skill applies when a task touches a policy that should be centralized, row-level filtering of Eloquent queries, a child model with the access of its parent, the `make:control`, `make:perimeter` and `access:*` commands, or the classes of the `Lomkit\Access\` namespace. It describes:

- controls, their discovery and `#[ControlledBy]`, and the `Access` facade;
- perimeters, their callbacks and hooks, levels, boundaries and `ThroughParent`;
- the policies, their refusal codes, drafts and business abilities;
- the controlled queries and the batched decisions;
- the Laravel Scout search: search keys, engines, freshness, browser tokens and an index of your own;
- the laravel-rest-api extension, `access:check` and the test assertions;
- the pitfalls to flag when reviewing or writing code.

## llms.txt and Markdown pages

The site publishes its pages in formats that assistants read directly:

| URL | Content |
| --- | --- |
| [`/llms.txt`](https://laravel-access-control.lomkit.com/llms.txt) | The list of every page, with a description and a link to its Markdown copy |
| [`/llms-full.txt`](https://laravel-access-control.lomkit.com/llms-full.txt) | Every page in one Markdown file |
| `/raw/<page>.md` | The Markdown copy of one page, such as [`/raw/essentials/perimeters.md`](https://laravel-access-control.lomkit.com/raw/essentials/perimeters.md) |

Both files cover 1.x only. Give an assistant `llms.txt` and let it open the pages it needs, or give it `llms-full.txt` when it can read a long file.

The **Copy page** button at the top of each page copies its Markdown. Its menu copies the link to the Markdown copy, opens it, or opens ChatGPT or Claude with a prompt that points to it.

## GitMCP

[GitMCP](https://gitmcp.io) serves a GitHub project as a remote MCP server. Its address for this site, `https://lomkit.gitmcp.io/laravel-access-control-doc`, reads the `llms.txt` of the site, and its tools let the assistant search the docs and fetch the Markdown copy of any page. Add the server to your assistant:

::code-group

```bash [Claude Code]
claude mcp add --transport http laravel-access-control https://lomkit.gitmcp.io/laravel-access-control-doc
```

```json [Cursor: .cursor/mcp.json]
{
  "mcpServers": {
    "laravel-access-control": {
      "url": "https://lomkit.gitmcp.io/laravel-access-control-doc"
    }
  }
}
```

```json [VS Code: .vscode/mcp.json]
{
  "servers": {
    "laravel-access-control": {
      "type": "http",
      "url": "https://lomkit.gitmcp.io/laravel-access-control-doc"
    }
  }
}
```
